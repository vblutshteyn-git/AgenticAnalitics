# Agentics Analytics

**Данные → инсайты.** Загружаете таблицу — агент профилирует её, строит семантическую
модель, формирует гипотезы, проверяет каждую статистически и возвращает только те
находки, которые прошли проверку: с доказательствами, трассировкой расчёта,
оговорками и следующими шагами.

Данные можно передать двумя способами: через веб-интерфейс или **через MCP**, чтобы
загрузку и анализ выполнял агент (Claude Desktop, Claude Code, любой MCP-клиент).

```bash
npm ci && npm run build && npm start
# http://127.0.0.1:4173
```

Нажмите «SaaS-подписки (демо)» и «Найти инсайты» — данные и заложенные в них
закономерности уже готовы.

Развёртывание на сервере — **[DEPLOY.md](DEPLOY.md)**: Docker и compose,
systemd-юнит, обратный прокси, чек-лист проверки, обновление, резервные копии
и разбор типичных проблем. Коротко, через Docker:

```bash
docker compose up -d --build
```

## Ключевое решение: числа считает код, слова пишет модель

Языковая модель в этой системе **никогда не производит числа**. Она делает ровно две
вещи: формулирует итоговый вывод из уже проверенных находок и переводит вопрос на
естественном языке в структурированный запрос, который затем исполняет
детерминированный движок.

Причина прагматична. Отраслевая критика MCP-подключённых агентов сводится к одной
фразе: *«MCP доставляет данные агенту, но не делает их правильными — агент,
подключённый к непроверенным таблицам, всё равно уверенно выдаёт неверные ответы»*.
Уверенно неверный ответ хуже отсутствия ответа, потому что ему верят.

Практическое следствие: **продукт полностью работоспособен без `ANTHROPIC_API_KEY`.**
Без ключа теряются только формулировки и вопросы словами; весь анализ, все находки и
все числа остаются на месте. Ключ — улучшение прозы, а не источник фактов.

## Семантический слой

Gartner в обзоре рынка agentic analytics за 2026 год прогнозирует, что **к 2028 году
60% проектов, опирающихся только на MCP, провалятся из-за отсутствия
согласованного семантического слоя**. Поэтому он здесь — первого класса, а не деталь
реализации.

При загрузке колонки автоматически разбираются на **метрики**, **измерения**,
**временные оси** и **идентификаторы**, с указанием аддитивности, направления
«хорошо/плохо» и единиц измерения. Агент — локальный или удалённый по MCP — читает
данные **только** через эту модель. Сырого SQL в системе нет вообще.

Что это даёт на практике:

- Агент не может сослаться на несуществующую колонку — запрос падает с подсказкой,
  а не возвращает правдоподобный мусор.
- Агент не может просуммировать отношение. Запрос `sum(margin_rate)` автоматически
  превращается в среднее, и подмена объясняется в ответе. Это самый частый способ
  получить уверенно неверную аналитику, и он закрыт на уровне слоя.
- Пока модель не подтверждена человеком, уверенность **всех** выводов ограничена
  сверху. Автоматически угаданная модель не выдаёт себя за подтверждённую.

## Цикл data-to-insight

```
приём → профилирование → семантическая модель → контроль качества →
гипотезы → проверка → верификация → ранжирование → формулировка
```

Ход работы транслируется в интерфейс по SSE. Это не украшение: видеть, что из 93
гипотез подтвердились 14, — и есть то, что делает эти 14 достойными доверия.

**Что проверяется:** тренды (МНК со значимостью наклона и обнаружением сдвига
уровня), аномалии (робастная z-оценка по медиане и MAD), драйверы изменений
(разложение на эффект объёма и эффект значения), различия сегментов (тест Уэлча с
размером эффекта), концентрация (Джини, Херфиндаль), взаимосвязи (Пирсон плюс
Спирмен), качество данных.

### Что система отказывается сообщать

Отсеивание — не менее важная часть работы, чем поиск:

- **Поправка на множественность.** Процедура Бенджамини–Хохберга применяется ко всем
  p-значениям прогона. При 200 гипотезах и α = 0.05 около десяти «находок»
  появляются по построению; без поправки продукт стабильно изобретал бы
  закономерности. Тест `на чистом шуме не выдумывает закономерностей` фиксирует это
  поведение.
- **Драйвер, пропорциональный своему размеру, — не драйвер.** Сегмент с 90% объёма
  даёт 90% любого изменения; сообщать об этом — тавтология. Порогом служит
  *превышение* доли в изменении над долей в объёме.
- **Размер эффекта важнее p-значения.** На 100 000 строк различие в 0,5% значимо и
  при этом операционно бессмысленно. Сравнение сегментов ведёт d Коэна.
- **Неполные граничные периоды исключаются.** Выгрузка почти никогда не
  заканчивается ровно на границе периода, и последний неполный интервал выглядит как
  обвал сразу во всех метриках. Это самая частая ложная тревога в реальных
  дашбордах, и она целиком артефакт того, где остановилась выгрузка.
- **Модель против модели.** Тренд и сдвиг уровня — конкурирующие объяснения с равным
  числом параметров; побеждает тот, что оставляет меньше необъяснённой дисперсии, а
  не тот, что сработал первым.

Отсутствие находок — валидный результат, и он так и формулируется.

## Подключение по MCP

Сервер работает по обоим транспортам. Веб-интерфейс и MCP делят одно хранилище:
набор, загруженный агентом, сразу виден в браузере, и наоборот.

```jsonc
// stdio — для Claude Desktop / Claude Code
{ "mcpServers": { "agentics-analytics": {
    "command": "node",
    "args": ["/путь/к/AgenticAnalitics/dist/mcp/stdio.js"]
} } }

// streamable HTTP — когда сервер уже запущен
{ "mcpServers": { "agentics-analytics": {
    "type": "http", "url": "http://127.0.0.1:4173/mcp"
} } }
```

| Инструмент | Назначение |
|---|---|
| `upload_dataset` | Загрузить CSV/TSV/JSON/NDJSON как текст; возвращает `dataset_id` и семантическую модель |
| `list_datasets` | Перечислить загруженные наборы |
| `get_semantic_model` | Как система поняла колонки — проверить до анализа |
| `update_semantic_model` | Исправить трактовку; подтверждение снимает ограничение уверенности |
| `profile_dataset` | Статистика по колонкам: пропуски, распределения, покрытие по времени |
| `analyze_dataset` | Полный цикл; возвращает проверенные находки с доказательствами |
| `get_insights` | Результаты последнего прогона без пересчёта |
| `query_data` | Запрос через семантическую модель (не SQL) |
| `ask` | Вопрос словами → структурированный запрос → детерминированный расчёт |
| `delete_dataset` | Удалить набор |

## Структура

```
src/
├── core/        приём данных, профилирование, статистика, семантика, запросы, хранилище
├── analysis/    анализаторы: тренд, аномалии, драйверы, сравнение, концентрация,
│                взаимосвязи, качество — каждый возвращает находку с доказательствами
├── agent/       оркестратор цикла + необязательный слой языковой модели
├── mcp/         MCP-сервер (stdio и streamable HTTP)
├── server/      HTTP API и SSE
├── web/         фронтенд без сборки: HTML + CSS + ES-модули, SVG-графики вручную
├── tools/       демо-наборы с заложенной структурой
└── test/        тесты
```

Зависимостей четыре: MCP SDK, Anthropic SDK, Zod и TypeScript. У фронтенда их нет
вообще — браузер получает ровно те файлы, что лежат в репозитории.

## Тесты

```bash
npm test
```

Статистика сверяется с аналитическими значениями (табличное `t`, Джини на
вырожденных распределениях, монотонность Бенджамини–Хохберга), а агент — с
демо-наборами, в которые закономерности заложены заранее. Движок, который ни разу
не проверяли на известном ответе, доверия не заслуживает, как бы уверенно он ни
формулировал.

Отдельный тест прогоняет агента по чистому шуму и требует, чтобы он ничего не нашёл.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `ANTHROPIC_API_KEY` | Включает формулировки и вопросы словами. Без неё анализ работает полностью. |
| `AGENTICS_MODEL` | Модель, по умолчанию `claude-opus-5`. |
| `AGENTICS_DATA_DIR` | Каталог данных, по умолчанию `~/.agentics-analytics`. |
| `PORT` / `HOST` | По умолчанию `4173` / `127.0.0.1`. |

## Ограничения

- Хранилище — в памяти с зеркалированием на диск; практический потолок около
  500 000 строк на набор. Это инструмент анализа, а не хранилище.
- Сезонность не моделируется: недельные и годовые циклы могут выглядеть как аномалии
  на коротких рядах. В оговорках это указывается явно.
- Разложение на эффект объёма и эффект значения не единственно возможное — результат
  зависит от того, какой фактор фиксируется первым. Тоже указано в оговорках.
- Все находки наблюдательные. Система нигде не утверждает причинность и явно
  предлагает проверку вмешательством там, где это уместно.
- Сервер по умолчанию слушает `127.0.0.1` и не имеет аутентификации. Прежде чем
  открывать его наружу, поставьте перед ним обратный прокси с авторизацией.
